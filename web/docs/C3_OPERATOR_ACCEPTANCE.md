# Final QC operator and author acceptance

C3 is an inspection stage, not a release publisher. Use a current author-approved C2 version, select Final QC, queue inspection, register its exact worker result. The UI lists deterministic findings and distinct Human claim/citation/Methods/RoB/visual items. Each Human item requires a rationale; correction-required does not waive a finding. Fix deterministic BLOCKER/MAJOR issues upstream, reapprove and rerun. Generic Human Gate approval cannot bypass this route.

Machine QC compares raw protected numbers and tables to approved registry; no statistical recalculation or manual PRISMA totals. Study counts and report counts are distinct. Missing required sources/actions remain blocking. Review the actual Word and every selected figure for clipping/glyph errors/overlap. Reference existence is not claim support; review source papers.

Required development dependencies are the existing Web/manuscript libraries plus operator-installed `pdftotext` for bounded inspection of text-based canonical PDFs. No OCR is required. The exact approved Word is never regenerated by C3. QC JSON is an authorized registry artifact; no Download Center/release ZIP is implemented.

Put the operator-installed Poppler executable directory on the Web process's PATH. For primary-outcome lookup, the operator can also set `SRMA_PDFTOTEXT` to the absolute path of the installed `pdftotext` executable before starting Web R. The Advanced view distinguishes an unavailable reader, unreadable or oversized files, and a bounded range without extractable text. Only registered PDFs in the exact Evidence snapshot with matching SHA-256 are searched.

Scientific release requires real locked runtime and real PostgreSQL acceptance. A historical development-runtime analysis or Word does not become canonical merely because the current server changes. Carry-forward scientific/AI/manuscript provider gates remain separately pending; deterministic Human-authored QC does not fabricate provider results.

The Advanced R/40 inspection can reuse an approved exact-version standalone receipt or queue an independent, offline Worker inspection of a current author-approved manuscript. The Worker checks registered source bytes and uses the existing narrative or pairwise deterministic validators. Its receipt records execution, verification and approval separately. Narrative coverage compares the archived Results with the frozen study rows and checks registered citations and DOCX structure. Pairwise coverage checks protected facts, tables and citations and inspects DOCX XML when the Web runtime provides `xml2`. A subset receipt cannot satisfy the standalone R/40 submission gate. The full CLI requires the R/38 and R/39 production dossiers and credentialed semantic mapping and consistency. A future full execution route requires explicit authorization and enforceable cost controls for those provider calls.

The Phase B bound inspection requires the complete approved input contract before queuing and revalidates the fingerprint when the Worker claims the job. It stages verified CLI inputs in a fresh attempt directory and uses the exact scientific runtime. Eligible quantitative inputs must bind to the original, noncolliding R/27 result paths. Its native CLI preflight stops before a provider call. The scientific matrix remains pending beyond the available checks. A successful Worker attempt publishes an unreviewed inspection, so the existing final approval rules still apply. Dedicated R/38 and R/39 producer jobs outside the manuscript's direct lineage must identify the exact evidence and protocol source versions. R/39 must also identify its R/38 source and manuscript versions. An approved standalone receipt used for release carries the current `validation_fingerprint`, `validation_ruleset` and `validation_checks`. Each outstanding required check points to a registered evidence artifact of the same manuscript version and its SHA-256.

In Phase C, the Advanced bound inspection can start from the current frozen draft. The Worker publishes whatever deterministic checks it can run and records the remaining prerequisites. Final submission still requires the existing author, scientific and release approvals. Exact Phase C results can follow an approval-only manuscript version when its archived bytes and upstream sources are unchanged. Approved input dossier files still belong to the existing Canonical Registry. If the approved configuration requires PubMed re-verification, the Worker needs the approved R/39 artifact `results/manuscript/production/drafting/pubmed_reference_reverification.xml` from the same producer version. Missing records remain pending.

The operator can print the current execution fingerprint with `Rscript --vanilla web/bin/r40_authorize.R USER_ID PROJECT_ID VERSION_ID`. Use the same command with the path to a separately approved JSON grant to record the authorization, or append `--revoke` to stop future paid calls for the same scope. The JSON requires `fingerprint`, `operator` (the matching authenticated member ID), `explicit_paid_approval`, fixed dated `model`, `rate_source`, `model_context_tokens`, Unix `expires_at`, integer `budget_microusd`, `max_input_tokens`, `max_output_tokens`, and the three micro-USD-per-million token rates `input_microusd_per_million`, `cached_input_microusd_per_million`, and `output_microusd_per_million`. Reserve the full model context and both maximum outputs before granting. Set `SRMA_R40_ALLOW_PAID=1` only on the Worker after separate PM approval. Supply the credential via the existing operator environment. The grant contains no credential.

The private data root holds the append-only `r40-ai` journal. All Workers sharing a job must share that private storage with atomic directory creation and rename. The maximum request charges are reserved before transport. The response records use actual provider token counts and the approved rate schedule. Provider invoice reconciliation remains an operator task. A reservation with an unknown provider outcome remains blocked and must be reconciled before a replacement run can be authorized. Completed responses replay without a new charge. Do not delete reservations to retry a request.

### P1-R native manuscript input recovery

Stage the exact approved sources in a new, isolated project directory. The version-bound R/38 intake reads `config/generated/r38_input_binding.yml`. Its schema is `SRMA_R38_INPUT_BINDING_V1` with the canonical `project_id`, `protocol_version`, `evidence_version`, and a named `analyses` map from executed group to approved analysis version. Each `sources` entry records a project-relative `path`, exact `sha256`, `source_version`, `approval_state` and `approval_id` from the Canonical Registry. Local binding metadata documents the upstream approval. Registry registration and author review remain separate.

The entries `protocol`, `evidence`, `selection`, `search`, `prisma_registry`, `prisma_audit`, `prisma_exclusions` and `prisma_figure` are required. Use `rob` for the final R/37 CSV when RoB applies, and `certainty` for the approved assessment covering required groups or Protocol outcome IDs. Set `protocol.synthesis_method` from the approved Protocol. The `narrative_results` CSV preserves the frozen verified-row fields `result_id`, `study_id`, `analysis_group`, `original_outcome`, `reported_timepoint`, `analysis_timepoint`, `decision`, `source_location`, `source_evidence`, `pdf_sha256`, `source_digest` and `verified_by`. R/38 reads the actual reported values from the matching Human review in the Evidence packet. For an executed pooled group, add its four R/27 artifacts as `group/basename` and the existing required quantitative aggregate files by canonical relative path. A bound mixed dossier needs both sets of verified sources.

Run the pinned R/38 from the isolated project root. Then invoke the pinned R/39 with `--preflight` from that same root. The preflight validates the state, registry, artifact catalogue, Methods, Results and scaffold against the bound R/38 checksums. It exits before drafting, PubMed or provider access. The existing Web draft, citation map and DOCX can be retained as historical, exact-version evidence. Native R/39 generation needs separate authorization for its PubMed and paid drafting stages, and subsequent registration under a new source version with its own provenance and review.

Operator-only commands (not browser actions):

```sh
Rscript --vanilla web/tests/c3_operator_acceptance.R CANONICAL_RUNTIME
Rscript --vanilla web/tests/c3_operator_acceptance.R POSTGRESQL
```

Runtime mode calls the existing exact R/lock probe and actual canonical C1/C2 reproduction, with no development seam. Configure SRMA_SCIENTIFIC_RSCRIPT and SRMA_SCIENTIFIC_LIBRARY. PostgreSQL mode needs SRMA_WEB_DB=postgres and a disposable EMPTY database owned by an unprivileged role; no reset/drop/superuser workaround. Standard libpq environment is operator-private. Each success stores append-only evidence with engine/lock/Web-code hash; code changes require repeat acceptance. Runtime reproduction uses non-private synthetic fixtures, never publishes them. No external acceptance success is asserted by shipped test logs.

Production DB backup is required before migrations 012/013. Services must be stopped when switching committed source. Prior versions, acceptance records and gates are immutable. Do not downgrade a migrated DB or apply over a dirty checkout.
