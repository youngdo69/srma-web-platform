# Final QC operator and author acceptance

C3 is an inspection stage, not a release publisher. Use a current author-approved C2 version, select Final QC, queue inspection, register its exact worker result. The UI lists deterministic findings and distinct Human claim/citation/Methods/RoB/visual items. Each Human item requires a rationale; correction-required does not waive a finding. Fix deterministic BLOCKER/MAJOR issues upstream, reapprove and rerun. Generic Human Gate approval cannot bypass this route.

Machine QC compares raw protected numbers and tables to approved registry; no statistical recalculation or manual PRISMA totals. Study counts and report counts are distinct. Missing required sources/actions remain blocking. Review the actual Word and every selected figure for clipping/glyph errors/overlap. Reference existence is not claim support; review source papers.

Required development dependencies are the existing Web/manuscript libraries plus operator-installed `pdftotext` for bounded inspection of text-based canonical PDFs. No OCR is required. The exact approved Word is never regenerated by C3. QC JSON is an authorized registry artifact; no Download Center/release ZIP is implemented.

Scientific release requires real locked runtime and real PostgreSQL acceptance. A historical development-runtime analysis or Word does not become canonical merely because the current server changes. Carry-forward scientific/AI/manuscript provider gates remain separately pending; deterministic Human-authored QC does not fabricate provider results.

Operator-only commands (not browser actions):

```sh
Rscript --vanilla web/tests/c3_operator_acceptance.R CANONICAL_RUNTIME
Rscript --vanilla web/tests/c3_operator_acceptance.R POSTGRESQL
```

Runtime mode calls the existing exact R/lock probe and actual canonical C1/C2 reproduction, with no development seam. Configure SRMA_SCIENTIFIC_RSCRIPT and SRMA_SCIENTIFIC_LIBRARY. PostgreSQL mode needs SRMA_WEB_DB=postgres and a disposable EMPTY database owned by an unprivileged role; no reset/drop/superuser workaround. Standard libpq environment is operator-private. Each success stores append-only evidence with engine/lock/Web-code hash; code changes require repeat acceptance. Runtime reproduction uses non-private synthetic fixtures, never publishes them. No external acceptance success is asserted by shipped test logs.

Production DB backup is required before migrations 012/013. Services must be stopped when switching committed source. Prior versions, acceptance records and gates are immutable. Do not downgrade a migrated DB or apply over a dirty checkout.
