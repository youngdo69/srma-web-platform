# Reviewing evidence in the Web workspace

1. Select a saved B1 database-input version and complete its database preflight. Under Screening / Evidence, start an evidence review. Approve the pending protocol gate in Human Review Required, then queue preparation and save the completed result as a new version.
2. Review title/abstract and source information. Each reviewer saves their own decision; a different reviewer completes the independent review. Use the uncertain/potential-conflict queue to locate disagreements. The queue is a navigation aid; canonical finalization determines conflicts. A separate adjudicator resolves them. Uncertain records must be resolved before finalization.
3. Save the full-text processing result. Upload each PDF against its report, then queue Register uploaded full-text PDFs. Registered PDFs are downloadable through authorized Results / Artifacts. A PDF must be at most 20 MB, have a PDF signature and use a simple filename. The application does not claim that signature checking is malware detection or complete PDF validation.
4. Map reports to study IDs explicitly: several reports can share one study ID. Enter Human Include/Exclude decisions; every exclusion needs a controlled reason. Review pending decisions and explicitly approve the inclusion gate. Finalize, then save the immutable included-set result.
5. Prepare structured extraction. Select study or outcome rows, enter reported values and source evidence/location, retain raw values and transformation rules for derived values. Add another outcome/timepoint row when needed. Select Yes only for outcomes intended for analysis; a second person must explicitly verify relevant study/outcome rows. Edits clear verification. Approve the extraction gate and run canonical validation.
6. Prepare bias assessment. Instrument/domain/question definitions come from the canonical engine. Record Human domain judgments and rationale, then Human overall judgment and rationale. Changing a signalling answer requires renewed domain/overall review; changing a domain requires renewed overall review. Approve the RoB gate and finalize the evidence package.

Every save creates a new ProjectVersion. Select/load the newly saved version before continuing. Earlier approved versions remain readable; they are never silently updated. Editing eligibility removes downstream extraction/RoB from the new revision. Editing extraction invalidates its analysis-ready and RoB outputs. A changed version requires new stage approval.

AI assistance is optional. Request it only on the selected stage; operator credentials and validated scientific runtime are required. AI rows are separate, labeled AI RECOMMENDATION — HUMAN REVIEW REQUIRED / UNVERIFIED. Record accept-for-manual-entry, reject or uncertain with a rationale. Accepting a proposal does not copy it into Human values or count as verification: enter the chosen values explicitly and follow the Human gate. Previous recommendations and overrides remain in immutable version history.

The final state is the canonical human_verified_dataset plus finalized RoB and report-study crosswalk, with job/version/engine and input hashes. Outputs remain individually checksum-protected registered artifacts. This is preparation for later analysis, not execution of meta-analysis, plots, manuscript or release generation.
